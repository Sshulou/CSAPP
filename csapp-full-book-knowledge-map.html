第 1 章：计算机系统漫游

主线：从 hello 程序出发，观察一个应用程序从源码到运行结果所经过的系统层次。

位与上下文

  • 计算机中的信息本质上是位序列。
  • 同一位模式可解释为数字、字符、指令或地址。
  • 类型、位置和执行阶段决定解释方式。

编译系统

  • 预处理把头文件和宏展开为新的 C 文本。
  • 编译把 C 程序转为汇编程序。
  • 汇编把汇编文本转为目标文件。
  • 链接合并目标文件和库函数，生成可执行文件。

处理器执行

  • Shell 读取命令并启动程序。
  • 操作系统加载可执行文件。
  • CPU 从内存取指、译码、执行。
  • 指令控制数据在寄存器、内存和 I/O 之间移动。

系统抽象

  • 进程抽象处理器、内存和 I/O。
  • 虚拟内存抽象主存和磁盘。
  • 文件抽象所有 I/O 设备。
  • 网络可以视为特殊的 I/O 设备。

概念关系

  1. 源代码 → 编译系统 → 可执行文件。
  2. 可执行文件 → 加载到内存 → CPU 执行指令。
  3. CPU、内存、I/O → 操作系统抽象 → 应用程序接口。

学习重点

  • 建立全局视角，后续章节都是对本章节点的展开。
  • 理解性能问题通常来自数据移动，而不只是计算。

第 2 章：信息的表示和处理

主线：位模式如何表示整数和浮点数，以及有限位宽如何影响程序正确性。

信息存储

  • 字节是最小可寻址单位。
  • 虚拟地址空间把内存看成字节数组。
  • 十六进制便于表示和转换位模式。
  • 字长决定指针大小和地址范围。

整数表示

  • 无符号数表示非负整数。
  • 补码表示有符号整数。
  • 零扩展、符号扩展和截断都会改变位级表示。
  • 有符号与无符号混用会触发隐式转换。

整数运算

  • 无符号运算按模 2^w 计算。
  • 补码运算可能溢出。
  • 乘除以 2 的幂可用移位实现。
  • 机器整数不是数学整数。

浮点数

  • IEEE 浮点由符号位、阶码和尾数组成。
  • 包含规格化数、非规格化数和特殊值。
  • 舍入和精度误差是浮点运算的常态。
  • 浮点运算不完全满足实数运算规律。

概念关系

  1. 位模式 → 类型解释 → 数值含义。
  2. 固定字长 → 溢出和截断 → 边界缺陷。
  3. 浮点近似 → 舍入误差 → 比较和累加风险。

学习重点

  • 把类型转换当成位解释规则变化来理解。
  • 写边界判断时警惕溢出和 unsigned 转换。

第 3 章：程序的机器级表示

主线：把 C 程序翻译成机器级代码，理解数据、控制、过程调用和内存布局。

程序编码

  • 编译器生成汇编，汇编器生成机器码。
  • 反汇编可从目标代码观察指令序列。
  • ISA 定义机器级程序可见的寄存器、指令和内存模型。

数据与寻址

  • 整数、指针和浮点数有不同机器级格式。
  • 寄存器保存临时数据和地址。
  • 寻址模式描述如何计算内存地址。
  • 数组和结构体最终表现为地址偏移。

控制流

  • 条件码记录算术和逻辑结果属性。
  • 条件跳转实现 if、switch 和循环。
  • 条件传送可减少分支预测失败成本。

过程与栈

  • 调用约定规定参数传递和返回值位置。
  • 栈帧保存返回地址、局部变量和被保存寄存器。
  • 缓冲区溢出源于越界写破坏栈上控制信息。

概念关系

  1. C 表达式 → 指令序列 → 寄存器和内存操作。
  2. 高级控制结构 → 条件码和跳转 → 机器级控制流。
  3. 函数调用 → 调用约定和栈帧 → 安全边界。

学习重点

  • 能从汇编反推 C 程序的数据和控制结构。
  • 理解指针、数组、结构体和栈的机器级本质。

第 4 章：处理器体系结构

主线：用简化指令集理解处理器如何取指、译码、执行、访存和写回。

指令集体系结构

  • ISA 是软件和硬件之间的契约。
  • Y86-64 用较小指令集展示处理器实现。
  • 程序状态包括寄存器、条件码、PC、内存和状态码。

顺序实现

  • 取指从内存读取当前指令。
  • 译码读取寄存器操作数。
  • 执行由 ALU 完成计算或地址生成。
  • 访存读写数据内存。
  • 写回更新寄存器，更新 PC 进入下一条指令。

流水线

  • 把指令执行拆成多个阶段并重叠执行。
  • 吞吐率提升，但单条指令延迟未必下降。
  • 流水线寄存器隔离各阶段状态。

冒险与控制

  • 数据冒险来自指令间的数据依赖。
  • 控制冒险来自分支和跳转。
  • 暂停、转发、预测和气泡用于维持正确性。

概念关系

  1. ISA 语义 → 数据通路 → 控制逻辑。
  2. 顺序执行 → 阶段拆分 → 流水线并发。
  3. 指令依赖 → 冒险 → 暂停、转发和预测。

学习重点

  • 区分 ISA、微体系结构和具体电路实现。
  • 理解流水线性能收益与正确性代价。

第 5 章：优化程序性能

主线：从代码、编译器和现代处理器行为出发，识别并消除性能瓶颈。

性能度量

  • 用每元素周期数等指标比较程序性能。
  • 基准测试需要稳定输入和可重复环境。
  • 性能优化必须围绕热点路径。

编译器能力与限制

  • 编译器能做局部和全局优化。
  • 别名、函数副作用和内存可见性会限制优化。
  • 写法影响编译器能否安全重排代码。

代码级优化

  • 消除循环中的低效率计算。
  • 减少不必要的函数调用和内存访问。
  • 循环展开降低循环控制开销。
  • 多路累积提高指令级并行度。

处理器约束

  • 延迟界限来自数据依赖链。
  • 吞吐量界限来自功能单元能力。
  • 分支预测失败和缓存未命中会显著拉低性能。

概念关系

  1. 程序热点 → 性能度量 → 优化目标。
  2. 代码结构 → 编译器优化空间 → 机器级性能。
  3. 数据依赖和资源限制 → 延迟 / 吞吐界限 → 优化上限。

学习重点

  • 不要凭感觉优化，先测量再定位瓶颈。
  • 理解优化收益受到 Amdahl 定律约束。

第 6 章：存储器层次结构

主线：理解不同存储设备的速度、容量和成本差异，并利用局部性写出缓存友好代码。

存储技术

  • SRAM 快且贵，常用于缓存。
  • DRAM 容量大，常用于主存。
  • 磁盘和固态存储容量更大但访问更慢。
  • 总线和 I/O 桥影响数据传输路径。

局部性

  • 时间局部性：最近访问的数据可能再次访问。
  • 空间局部性：相邻数据可能很快被访问。
  • 循环和数组访问顺序强烈影响局部性。

缓存结构

  • 缓存由组、行和块组成。
  • 地址被拆分为标记、组索引和块偏移。
  • 直接映射、组相联和全相联权衡命中率与复杂度。
  • 写策略影响一致性和性能。

缓存友好代码

  • 顺序访问数组通常优于跨步访问。
  • 提高数据重用可增加缓存命中。
  • 分块技术让工作集适配缓存容量。
  • 矩阵运算是局部性优化的典型场景。

概念关系

  1. 存储技术差异 → 层次结构 → 缓存机制。
  2. 程序访问模式 → 局部性 → 命中率。
  3. 命中率和未命中代价 → 平均访问时间 → 程序性能。

学习重点

  • 把缓存看成较低层存储的自动缓存。
  • 用访问顺序和分块控制工作集大小。

第 7 章：链接

主线：多个目标文件和库如何被解析、重定位并组合成可执行程序或共享库。

目标文件

  • 可重定位目标文件保存代码、数据、符号和重定位信息。
  • 可执行目标文件可被加载器直接加载运行。
  • 共享目标文件支持运行时动态链接。

符号解析

  • 符号表示函数或全局变量等可链接实体。
  • 链接器把引用绑定到定义。
  • 强弱符号规则影响重复定义处理。
  • 静态库解析受命令行顺序影响。

重定位

  • 合并同类节并确定运行时地址。
  • 修改代码和数据中的地址引用。
  • 重定位项告诉链接器如何修补引用位置。

动态链接

  • 共享库减少磁盘和内存重复。
  • 位置无关代码支持库加载到不同地址。
  • 运行时链接允许程序显式加载库。
  • 库打桩可用于调试、监控和替换函数行为。

概念关系

  1. 编译单元 → 目标文件 → 符号表。
  2. 符号引用 → 符号解析 → 定义绑定。
  3. 节合并和地址分配 → 重定位 → 可执行文件。

学习重点

  • 理解链接错误通常来自符号解析或库顺序。
  • 区分静态链接、动态链接和运行时加载。

第 8 章：异常控制流

主线：程序执行并不总是顺序推进，异常、进程、信号和非本地跳转会改变控制流。

异常

  • 异常是控制流对处理器状态变化的响应。
  • 包括中断、陷阱、故障和终止。
  • 系统调用通过陷阱进入内核。

进程

  • 进程提供独立逻辑控制流。
  • 上下文切换让多个进程共享处理器。
  • 进程拥有私有虚拟地址空间。

进程控制

  • fork 创建子进程。
  • execve 加载并运行新程序。
  • wait / waitpid 回收子进程。
  • exit 终止当前进程。

信号与跳转

  • 信号是进程级异常通知。
  • 信号处理函数异步改变程序控制流。
  • 阻塞和解除阻塞用于控制信号交付。
  • setjmp / longjmp 支持非本地跳转。

概念关系

  1. 异常 → 内核介入 → 控制流改变。
  2. 进程抽象 → 上下文切换 → 并发执行假象。
  3. 信号 → 异步事件处理 → 竞态和可重入风险。

学习重点

  • 掌握 fork 后父子进程执行路径差异。
  • 信号处理要避免复杂共享状态操作。

第 9 章：虚拟内存

主线：虚拟内存把主存、磁盘、地址翻译、保护和动态分配统一到一个抽象中。

地址空间

  • 虚拟地址由程序生成。
  • 物理地址对应主存位置。
  • 每个进程看到独立的虚拟地址空间。
  • 虚拟内存同时承担缓存、管理和保护职责。

地址翻译

  • 页表把虚拟页映射到物理页。
  • MMU 执行地址翻译。
  • TLB 缓存常用页表项。
  • 缺页会触发内核处理并从磁盘调入页面。

内存映射

  • 文件可映射到虚拟内存区域。
  • 共享映射支持进程间共享数据。
  • 私有映射通过写时复制提高效率。
  • 加载程序也依赖内存映射机制。

动态内存分配

  • 堆由分配器管理。
  • 显式分配需要 malloc 和 free 配对。
  • 隐式空闲链表、显式空闲链表和分离适配是常见策略。
  • 碎片会降低内存利用率。

概念关系

  1. 虚拟地址 → 页表 / TLB → 物理地址。
  2. 虚拟页 → 物理页或磁盘页 → 主存作为缓存。
  3. 堆请求 → 分配策略 → 吞吐率和利用率。

学习重点

  • 理解虚拟内存为何能隔离和保护进程。
  • 掌握 C 程序常见内存错误的根因。

第 10 章：系统级 I/O

主线：Unix 把设备、文件和网络统一为文件接口，程序通过系统调用读写字节序列。

Unix I/O

  • 文件是字节序列。
  • 打开文件返回描述符。
  • read 和 write 以字节为单位传输数据。
  • close 释放描述符。

文件与元数据

  • 普通文件、目录和设备都可用文件视图处理。
  • stat 读取文件元数据。
  • 目录操作可遍历文件系统层次。

共享与重定向

  • 描述符表、文件表和 v-node 表共同描述打开文件。
  • fork 后父子进程共享打开文件状态。
  • dup2 可实现标准输入输出重定向。

健壮 I/O

  • 短计数是系统 I/O 的常见现象。
  • RIO 包封装可靠读写循环。
  • 标准 I/O 提供缓冲，但与系统 I/O 混用要谨慎。

概念关系

  1. 文件名 → open → 文件描述符。
  2. 描述符 → read / write → 字节流传输。
  3. 描述符复制 → 重定向 → Shell 管道和 I/O 控制。

学习重点

  • 理解描述符是进程访问 I/O 对象的句柄。
  • 处理 read / write 时必须考虑短计数。

第 11 章：网络编程

主线：基于客户端-服务器模型和套接字接口，构建跨主机通信程序。

客户端-服务器模型

  • 服务器管理资源并响应请求。
  • 客户端主动发起连接和请求。
  • Web 服务是典型的客户端-服务器应用。

网络基础

  • 网络把主机连接成可通信系统。
  • IP 地址标识主机接口。
  • 端口标识主机上的进程端点。
  • 域名通过 DNS 映射到地址。

套接字接口

  • socket 创建通信端点。
  • bind 绑定本地地址和端口。
  • listen / accept 让服务器接受连接。
  • connect 让客户端连接服务器。
  • read / write 可用于已连接套接字。

Web 与 Tiny

  • HTTP 请求和响应在 TCP 连接上传输。
  • 静态内容直接读取文件返回。
  • 动态内容通过 CGI 等机制生成。
  • Tiny Web 服务器综合使用 I/O、进程和网络。

概念关系

  1. 主机地址 + 端口 → 套接字地址 → 通信端点。
  2. 客户端 connect → 服务器 accept → 双向字节流。
  3. HTTP 协议 → 请求解析和响应生成 → Web 服务。

学习重点

  • 把网络连接看成特殊文件描述符。
  • 掌握客户端和服务器端套接字调用顺序。

第 12 章：并发编程

主线：用进程、I/O 多路复用和线程构建并发程序，同时处理共享状态带来的同步问题。

并发模型

  • 基于进程的并发隔离性好，通信成本较高。
  • I/O 多路复用用单进程管理多个描述符。
  • 基于线程的并发共享地址空间，切换成本较低。

线程基础

  • 线程是进程内的独立控制流。
  • 多个线程共享全局变量和堆。
  • 线程私有栈保存各自调用状态。
  • 线程创建、分离和回收影响资源管理。

共享变量与同步

  • 共享变量会引入竞态条件。
  • 临界区需要互斥保护。
  • 信号量可实现互斥和资源计数。
  • 生产者-消费者是同步的典型模式。

并发风险

  • 死锁来自循环等待等条件。
  • 活锁和饥饿会导致进展问题。
  • 线程不安全函数需要替代或保护。
  • 可重入性和线程安全性不是同一个概念。

概念关系

  1. 多个任务 → 并发模型选择 → 性能和复杂度权衡。
  2. 共享内存 → 竞态条件 → 同步机制。
  3. 同步约束 → 正确性 → 死锁和性能风险。

学习重点

  • 根据任务特征选择进程、多路复用或线程模型。
  • 并发代码的核心是明确共享状态和同步边界。
